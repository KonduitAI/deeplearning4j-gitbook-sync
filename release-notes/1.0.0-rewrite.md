# 1.0.0-rewrite

## Highlights

This release represents a ground-up rewrite of the Deeplearning4j ecosystem. The 22 open PRs ([#10435](https://github.com/deeplearning4j/deeplearning4j/pull/10435)–[#10456](https://github.com/deeplearning4j/deeplearning4j/pull/10456)) introduce capabilities that reposition DL4J as a first-class runtime for modern LLM and VLM workloads.

**Key areas of change:**

- **DSP (Dynamic Shape Plan) execution engine** — a compiled graph runtime with CUDA graph capture/replay, Triton/NVRTC/PTX JIT compilation, and a 26-pass graph optimizer ([#10442](https://github.com/deeplearning4j/deeplearning4j/pull/10442), [#10443](https://github.com/deeplearning4j/deeplearning4j/pull/10443), [#10444](https://github.com/deeplearning4j/deeplearning4j/pull/10444), [#10449](https://github.com/deeplearning4j/deeplearning4j/pull/10449))
- **Full LLM/VLM application stack** — generation pipelines, paged KV cache, speculative decoding, continuous batching, and a built-in eval framework ([#10452](https://github.com/deeplearning4j/deeplearning4j/pull/10452))
- **GGML/GGUF model import** — load quantized LLMs from `.gguf` files with 20+ architecture handlers and a complete set of quantization codecs ([#10451](https://github.com/deeplearning4j/deeplearning4j/pull/10451))
- **12 PEFT methods + 9 RL alignment trainers** for modern LLM fine-tuning and alignment ([#10448](https://github.com/deeplearning4j/deeplearning4j/pull/10448))
- **Massive hardware expansion** — Google Cloud TPU, Qualcomm Hexagon DSP, ZLUDA, Snapdragon X, ARM Compute Library, Apple Accelerate, and 17 execution modes ([#10441](https://github.com/deeplearning4j/deeplearning4j/pull/10441), [#10447](https://github.com/deeplearning4j/deeplearning4j/pull/10447))
- **DSP Runtime SDK** — stable C ABI with bindings for Java, Kotlin, Python, Rust, Swift, and C#
- **~130 new native ops** covering fused attention, KV cache, PEFT linear layers, SSM/recurrent blocks, and MoE ([#10446](https://github.com/deeplearning4j/deeplearning4j/pull/10446))
- **~120 new ONNX op implementations** including Microsoft LLM contrib ops ([#10450](https://github.com/deeplearning4j/deeplearning4j/pull/10450))

## DSP: Dynamic Shape Plan Execution Engine

**PRs:** [#10442](https://github.com/deeplearning4j/deeplearning4j/pull/10442), [#10443](https://github.com/deeplearning4j/deeplearning4j/pull/10443), [#10444](https://github.com/deeplearning4j/deeplearning4j/pull/10444), [#10449](https://github.com/deeplearning4j/deeplearning4j/pull/10449)

The DSP engine replaces the previous graph execution infrastructure with a compiled plan approach. A SameDiff graph is compiled once into a `DynamicShapePlan` that progresses through three lifecycle phases: warmup (slot-by-slot execution to learn tensor shapes) → shape freeze → CUDA graph capture → replay. Subsequent inference replays the captured CUDA graph, eliminating kernel launch overhead on hot paths.

### Native Engine (C++)

`NativeDynamicShapePlan` compiles serialized SameDiff plans into slot-based execution. `NativePlanCache` uses content-based keys (output hash + shape info + execution mode) with a dual eviction policy (count cap + memory budget). Multi-backend dispatch routes execution to CUDA, HIP, Vulkan, Metal, TPU, Hexagon, Level Zero, NNAPI, MLX, oneDNN, ACL, and MLIR backends.

### Graph Optimizer

`GraphOptimizer` applies 26 passes across 3 iterations. Selected passes:

| Pass | Description |
|------|-------------|
| 1 | Dead code elimination |
| 2 | Constant propagation |
| 3–4 | Broadcast elimination, commutative op canonicalization |
| 5–6 | Reassociation, double transpose elimination |
| 7 | Algebraic identities: `x+0→x`, `x*1→x`, `sqrt(x²)→abs(x)` |
| 8 | Peephole: `relu(relu(x))→relu(x)`, `log(exp(x))→x` |
| 9 | Arithmetic chain folding: `add(add(x,c1),c2)→add(x,c1+c2)` |
| 10 | Strength reduction: `pow(x,2)→square(x)`, `div(x,c)→mul(x,1/c)` |
| 11–14 | Identity removal, concat/split simplification, constant-condition select/where, redundancy elimination |
| 15 | Shape constant folding, common subexpression elimination |
| 16 | **Attention fusion**: detects `softmax(scale(matmul(Q,K^T)))@V` → `dot_product_attention_v2` |
| 17 | **Horizontal fusion**: parallel matmuls → batched matmul + slice (fused QKV projection) |
| 18–26 | Normalization fusion, gated delta network fusion, quantization optimization, and more |

Passes are configurable via `-Dnd4j.optimizer.skip=PassName` and `-Dnd4j.optimizer.logApplied`.

### GPU JIT Compilation

Three JIT backends with automatic fallback chain:

1. **Triton** (MLIR-based, highest fidelity)
2. **NVRTC** (runtime CUDA C compilation)
3. **PTX** (string-generated assembly, fastest compile time)

`OpCategoryTable` maps 100+ ops to GPU IR categories. `TritonIRBuilder` decomposes computation segments into typed `KernelSection`s (ELEMENTWISE, MATMUL, REDUCTION, NORMALIZATION, ATTENTION, and more). `TritonTargetDispatch` selects NVIDIA PTX, AMD AMDGCN, or Intel SPIR-V target as appropriate. A background precompilation thread compiles kernels during warmup so they are ready before the hot path needs them.

### Java Runtime

`DynamicShapePlanCompiler` compiles a `ForwardExecutionDAG` into a `DynamicShapePlan`. `DynamicShapePlanExecutor` manages the full lifecycle (warmup → shape freeze → CUDA graph capture → replay). `DspPlanDiskCache` persists compiled plans using FNV-1a keyed atomic file writes (default directory: `~/.kompile/cache/dsp/`). `DspDiagnostics` exposes per-category diagnostics at summary, detailed, and full verbosity levels.

```java
// DSP lifecycle
SameDiff sd = SameDiff.load(new File("model.fb"), false);
ForwardExecutionDAG dag = ForwardExecutionDAG.build(sd);
DynamicShapePlan plan = DynamicShapePlanCompiler.compile(dag);
DynamicShapePlanExecutor executor = new DynamicShapePlanExecutor(plan);

// Warmup phase — slot-by-slot execution to learn shapes
for (int i = 0; i < warmupSteps; i++) {
    executor.execute(inputs);
}

// Freeze shapes → CUDA graph capture → replay
executor.freezeShapes();
INDArray output = executor.execute(inputs);  // now replaying captured graph
```

### DSP Runtime SDK

Stable C ABI (`dsp_runtime_c.h`, ABI version 1) with sized structs for forward compatibility. Lifecycle: `sdxCreateRuntime()` → `sdxLoadBundle()` → `sdxCreateContext()` → `sdxRun()` → cleanup. `sdx_execution_report_t` reports `slotCount`, `executionMode`, `replayCount`, `avgLatencyUs`, and `peakMemoryBytes`.

Language bindings:

| Language | Mechanism |
|----------|-----------|
| Java | JNA |
| Kotlin | JNA (idiomatic wrappers) |
| Python | ctypes + numpy bridge + gRPC serving |
| Rust | FFI with RAII wrappers |
| Swift | Swift Package Manager |
| C# | P/Invoke |

```python
from sdx_runtime import SdxRuntime
runtime = SdxRuntime.create(backend="cuda")
model = runtime.load("model.sdnb")
ctx = model.create_context()
output = ctx.run(input_data)
print(ctx.get_execution_report())
```

## Training: PEFT & RL Alignment

**PR:** [#10448](https://github.com/deeplearning4j/deeplearning4j/pull/10448)

### Parameter-Efficient Fine-Tuning (PEFT)

`PeftModel` wraps an existing SameDiff model analogously to HuggingFace's `get_peft_model()`. `PeftModelFactory.fromConfig(sd, config)` dispatches to the correct adapter injection strategy. `mergeAndUnload()` absorbs adapter weights back into base model weights for deployment. `LoraAdapterCache` enables serving multiple LoRA adapters from a single base model.

**Supported `PeftType` values:**

`LORA`, `QLORA`, `DORA`, `LOHA`, `LOKR`, `IA3`, `VERA`, `PREFIX_TUNING`, `PROMPT_TUNING`, `ADAPTER`, `LOFTQ`, `ADALORA`, `DYLORA`

`LoraLayer` wraps existing linear ops with low-rank A/B matrices, keeping the base weight frozen during training.

### RL Alignment Trainers

Nine trainers build their loss graphs directly in SameDiff:

| Trainer | Algorithm |
|---------|-----------|
| `GRPOTrainer` | Group Relative Policy Optimization — generates `groupSize` completions, computes z-score advantages |
| `DPOTrainer` | Direct Preference Optimization |
| `DAPOTrainer` | Decoupled Clip and Dynamic Sampling Policy Optimization |
| `DrGRPOTrainer` | Variance-reduced GRPO |
| `PPOTrainer` | Proximal Policy Optimization with value network |
| `KTOTrainer` | Kahneman-Tversky Optimization |
| `ORPOTrainer` | Odds Ratio Preference Optimization |
| `SimPOTrainer` | Simple Preference Optimization (no reference model required) |
| `GSPOTrainer` | Grouped Sampling Policy Optimization |
| `VlmGRPOTrainer` | GRPO adapted for vision-language models |

`RewardModelTrainer` supports `CompositeRewardFunction`, `RuleBasedRewardFunction`, and `SameDiffRewardFunction`.

### Mixed Precision Training

`FP8ScaleManager` tracks per-tensor absmax for E4M3 (forward pass, max=448.0) and E5M2 (backward pass, max=57344.0). `LossScaler` implements dynamic scaling: scale doubles every 2000 steps and halves on NaN detection. `GradientCheckpointConfig` enables activation checkpointing to trade compute for memory.

### 8-bit Adam

`Adam8bit` uses INT8 per-block absmax quantization for the first and second moment states (block size 2048), reducing optimizer state memory approximately 4x (e.g., 56 GB → ~14 GB for a 7B-parameter model).

### Knowledge Distillation

`DistillationTrainer` supports configurable temperature and three distillation loss types: `DistillationKLLoss`, `AttentionDistillationLoss`, and `FeatureDistillationLoss`.

### Dataset Curation

| Class | Function |
|-------|----------|
| `TextDeduplicator` | MinHash LSH deduplication |
| `NGramDecontaminator` | Benchmark contamination removal |
| `TextQualityFilter` | Heuristic quality filtering |
| `CurriculumIterator` | Pluggable `DifficultyScorer` for curriculum learning |
| `SequencePacker` | Bin-packing to minimize padding |
| `WeightedDataMixer` | Domain-weighted data mixing |
| `LengthBucketingIterator` | Padding-free batching by sequence length |
| `InstructionDataFormatter` | Chat template application |

```java
// Apply LoRA to a model
LoraConfig config = LoraConfig.builder()
    .r(16)
    .loraAlpha(32)
    .loraDropout(0.05)
    .targetModules(".*attn_q.*", ".*attn_v.*")
    .build();

PeftModel peftModel = PeftModelFactory.fromConfig(sd, config);
peftModel.printTrainableParameters();
// trainable params: 4,194,304 || all params: 6,742,609,920 || trainable%: 0.0622

// Train with GRPO
GRPOConfig grpoConfig = GRPOConfig.builder()
    .groupSize(8)
    .clipEps(0.2)
    .klCoeff(0.1)
    .build();
GRPOTrainer trainer = new GRPOTrainer(peftModel.getSameDiff(), grpoConfig);
```

## ND4J Core Infrastructure

**PR:** [#10445](https://github.com/deeplearning4j/deeplearning4j/pull/10445)

### Framework Facade

`Framework.java` serves as the unified entry point for the ND4J runtime:

```java
Nd4j.framework.execution()    // DSP stats and mode control
Nd4j.framework.memory()       // Allocation and workspace tracking
Nd4j.framework.device()       // Transfer tracking, pointer stability
Nd4j.framework.workspaces()   // Workspace lifecycle
Nd4j.framework.profiling()    // Profiling subsystem
Nd4j.framework.lifecycle()    // Runtime lifecycle management
Nd4j.framework.diagnostics()  // Diagnostics and leak detection
```

Subsystems include `ExecutionSubsystem`, `DeviceSubsystem`, `MemorySubsystem`, `ProfilingSubsystem`, `LeakDetector`, and `ArrayLifecycleTracker`.

### Memory Coherence

`HybridDataBuffer` transparently mirrors host and device memory. `CoherenceState` tracks buffer status: `HOST_ONLY`, `DEVICE_ONLY`, `SYNCHRONIZED`. `MemoryCoherenceManager` handles automatic synchronization.

### Graph Tracing

`Nd4j.graphScope()` traces `GraphFunction` calls into hidden SameDiff graphs. `LazyINDArray` acts as a proxy during tracing. `CompiledGraphFunction` wraps the result for repeated DSP execution.

### New Op Namespaces

## Migration Guide

The following changes require attention when upgrading from 1.0.0-M2.1.

### New Maven Modules

Add any of the following to your `pom.xml` as needed:

```xml
<!-- LLM/VLM application stack -->
<dependency>
    <groupId>org.deeplearning4j</groupId>
    <artifactId>samediff-llm</artifactId>
    <version>1.0.0-rewrite</version>
</dependency>

<!-- GGUF model import -->
<dependency>
    <groupId>org.nd4j</groupId>
    <artifactId>nd4j-ggml</artifactId>
    <version>1.0.0-rewrite</version>
</dependency>

<!-- HuggingFace-compatible tokenizers -->
<dependency>
    <groupId>org.nd4j</groupId>
    <artifactId>nd4j-tokenizers</artifactId>
    <version>1.0.0-rewrite</version>
</dependency>
```

### Opting In to DSP Optimization

Graph execution mode defaults to `AUTO`. To explicitly select a mode:

```java
Nd4j.framework.execution().setMode(GraphExecutionMode.TRITON);
```

To skip specific optimizer passes during debugging:

```
-Dnd4j.optimizer.skip=AttentionFusion
-Dnd4j.optimizer.logApplied=true
```

### PEFT and Training APIs

The new PEFT and RL alignment APIs are additive. No existing training code requires changes unless you intend to adopt PEFT methods or alignment trainers.

### New Backend Options

Hardware backends (TPU, Hexagon, ZLUDA) are discovered automatically if the corresponding Maven module is on the classpath and the hardware is present. No code changes are required. See the Backend Expansion section above for module names.

### Serialization Compatibility

`DspPlanDiskCache` stores compiled plans in `~/.kompile/cache/dsp/` using a content-based key. The cache is invalidated automatically when model weights or shapes change. No manual cache clearing is required when upgrading.
